## 述語起草の能力測定 — 凍結 (RULING_Q5 = A)

**なぜ凍結するか**: 消費者 (human lane) の大きさが未確定のまま能力を作る形になる。
先に分母を確定させる。

**凍結時点の状態** (fixture 2 周目・`labs/das_adaptive_sampling/records/discrimination_result.json`):

```
L1 無関係(file数)  0.0    ← 1 周目は 1.0 で本命と同着だった退化解。死んだ
L2 部分相関        0.48
L3 近傍            0.0    ← **測定の欠陥**。性能ではない (下記)
本命(起草)         0.12
恒真/恒偽          0.0    (対照に数えない)
独立単位 19 (要 10) / class 3 種 / unmeasurable 11
```

**成立条件 3 (通りうる対照 < 本命) が不成立**なので、prereg の停止条件どおり
一致率を結果として扱わず、起草の合否も判定していない。

**L3 = 0.0 は測定の欠陥であって性能ではない** (自己反証 + agy/cursor cross-review 一致)。
`build()` は `cls` の変異しか注入しないので、L3 が探す other class の欠陥は
fixture に存在せず、構造的に (0,0) しか出せない。
**直したふりをせず欠陥として残す。** 修理には「同一 target に 2 種の欠陥を同時に
注入する」fixture が要る。
ただし成立条件不成立は **L2 0.48 > 本命 0.12 で独立に立つ**ので、
L3 の欠陥を理由に凍結時点の結論を取り消さない。

**fixture 3 周目は作らない。**

## Defects4J での選択器採点 — 基盤不適合

**なぜ閉じるか**: 合否や閾値の問題ではなく、**時点を巻き戻せない**ため。

`modified_classes` も `relevant_tests` も修正 patch 由来で、
「検査時点で入手可能な変更集合」を再現できない。
Defects4J README L213 が `relevant_tests` の定義を明示している —
「a test class is relevant if, when executed, the JVM loads at least one of the
**modified classes**」。

修正由来の subject を外すと `selector_pick` は `uniform_pick` と **恒等**になり、
対照との差が 0 件になって採点が成立しない (実測)。

**代替は発明しない。** 巻き戻せる基盤 (実 repo 履歴) へ移した = TASK-I。
